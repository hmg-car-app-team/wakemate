## 현재 상태 (feat/stimulus-hero-ui 첫 커밋 기준)

- 2단계 경고에서 공조 3종(외기·풍량 80%·온도 -2℃) + **운전석 시트 통풍 최대** + **실내 앰비언트 경고색**을 차량 capability 확인 후 쓴다.
- 주행 화면: 단계별 전면 색상 반전 히어로(정상/노랑/주황/빨강) + 아크 게이지 + 물리 자극 카드 3장.

- **미검증**: 실제 화면 렌더링(Pleos 에뮬레이터 없음), 시트·조명 SDK 실동작.

## 진행 현황 (19:10 KST 갱신)

- 주행 화면 구성 확정: 왼쪽 주행 섹션(차속·원근 차선·연속 주행) 위에 반투명 경고 카드(팝업 면 불투명도 80%), 오른쪽에 위험지수 게이지와 물리 자극 카드. 실제 앱 화면 캡처는 `docs/screens/` (Automotive 에뮬레이터 2560×1440, 시연 신호 주입). Pleos 실차에서는 왼쪽 시스템 주행 섹션이 따로 있고 앱은 오른쪽 앱 영역(1700dp)에서 이 구성으로 보인다

- 디자인 방향 변경(사용자 요청): 화면을 단계 색으로 채우지 않고 Pleos 기본 면을 그대로 둔다. 단계는 ① 화면 가장자리(베젤)부터 안쪽으로 번지는 단계 색 빛(실내 무드등과 같은 색 계열, 정차 중에는 절반 세기)과 ② 화면 위에 떠 있는 경고 카드(단계 칩·쉼터·작동 중인 장치)로 알린다. 게이지·카드 점만 단계 색. 다른 앱 위에 그리는 것은 오버레이 권한이 필요해 앱 창 안에서만 한다

- 완료: 1-1·1-2(P1, 자극 카드는 차량이 확인한 쓰기·실제 경고음만 "작동"), 1-3(P2·P7, 반전 배경은 어두운 글씨 + `ContrastTest` 고정), 1-4(P3, 주행 중 카드 설명 숨김·캡션 제거), 4-2(P5, 시트·조명 주행 제한 문구), 4-3(P6, 디자인시스템 하드코딩 문구 제거)
- 완료: 4-1(P4, 시트 통풍·무드등 원래 값 기억 → 휴식·정상 3분 뒤 복원), 3-2(README), unsigned release APK 빌드
- 완료(2단계 대체): 표준 Android Automotive API 34 에뮬레이터(2560×1440, 160dpi)에서 정차·주의·위험·쉼터 화면과 다크 모드 확인. 고친 것: 히어로 단계 이름을 색과 같은 단계로 통일, 주행 화면 히어로를 높이 80%로 확대(점수 128sp, 게이지 400dp), 정차 보조 패널의 카드 겹침 제거와 빠른 조작 버튼 이동, 한국어 어절 단위 줄바꿈

## 알려진 문제 (변경분 자체 점검 결과)

| ID | 문제 | 영향 |
|---|---|---|
| P1 | 자극 카드가 **단계·설정만 보고 "작동"으로 표시**한다. 시트·조명 미지원 차량이나 쓰기 실패에도 "통풍 각성 가동"이 뜬다 | 기존 앱의 "성공한 척 금지" 원칙 위반. 시연에서 거짓 표시 |

| P3 | 주행 중 자극 카드에 **2줄 설명**까지 표시 | 주의분산(DO) 가이드: 주행 중 읽을 글 최소화 |

| P5 | 주행 제한 오류 문구가 시트·조명에도 "공조를 바꿀 수 없어요" | 문구 부정확 |
| P6 | 디자인시스템 컴포넌트(`PleosStageHeroBanner`) 안에 앱 문구가 하드코딩 | 문구 관리·재사용성 |
| P7 | 다크 테마에서 정상 단계 활성 카드(파랑 #0082FF) 흰 글씨 대비 약 3.7:1 | P2와 같은 종류 |
