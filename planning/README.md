# 깨워드림 WakeMate 기획서 (접수양식 02장 초안)

> 팀명·대표자·연락처 등 참가자 정보는 **접수양식 01에 기재**합니다(이 문서에는 쓰지 않음).
> 이 문서의 "동작"은 모두 **Pleos Connect 에뮬레이터와 시연용 주입 신호, 한국도로공사 공공데이터 스냅샷(쉼터)** 기준입니다. 실차·실주행 결과가 아닙니다.
> **이 앱은 운전자 보조 도구이며 졸음운전을 막는다고 주장하지 않습니다.** 위험지수는 차량 신호 기반 **추정**이지 졸음의 직접 측정(카메라·생체 신호)이 아닙니다. 졸리면 즉시 안전한 곳에 정차해 쉬어야 합니다.
> 표기: **[기획 가정]** = 기획 원문의 가정(검증하지 않음), **[구현]** = 코드·테스트로 확인, **[미구현/미검증]** = 6장 한계 참조.

## 1. 앱 한 줄 소개

졸음이 오는 걸 스스로 알아차리기 어려운 장거리·야간 운전을, 차량 신호로 졸음 위험을 추정해 단계별로 알리고 쉼터를 안내하는 보조 앱으로 돕습니다.

## 2. 기획 배경

- **주목한 순간**: 장거리·야간·식후 운전처럼 졸음이 오는 순간, 운전자는 스스로 졸고 있음을 늦게 알아차릴 수 있습니다. (기획 원문의 문제 인식. 원문이 인용 예정이던 사고 통계는 확인하지 못해 이 문서에 싣지 않습니다.)
- **왜 차량인가**: 차량은 조향각·차속·기어·공조 상태를 알고, 공조 제어와 내비게이션을 연결할 수 있어 "알림 -> 환기 -> 휴식 안내"를 한 앱에서 이을 수 있다는 것이 기획 의도입니다. 이 연결이 실제 졸음 예방에 효과가 있는지는 측정한 바 없습니다.
- **주행 안전 관점**: 주행 중에는 화면 조작을 요구하지 않고 음성·경고음·읽기 전용 한 화면만 사용하도록 설계했습니다.

**차량 특화 요소**
- Pleos Vehicle SDK의 차속·기어·조향각·공조 상태 신호를 위험지수와 주행/정차 판정에 사용.
- 공조는 SDK 공개 API로 실제 제어(외기 순환·풍량·온도). 내비는 NaviHelper `addWaypoint`/`requestRoute` 연결.
- Landscape 2분할, Portrait 1단 레이아웃을 구현(Portrait 실화면은 미검증).

### 주행 안전 설계
- **DO(주의분산 최적화) 선언**: `distractionOptimized=true`.
- **정차/주행 UX 분리**: 주행 중에는 위험지수·단계·배너·연속 주행 시간만 보이는 읽기 전용 한 화면(버튼·입력 없음, 독립 검증에서 확인). 현황/쉼터/휴식 리포트/설정 4탭은 정차 시에만.
- **주행 중 사용자 터치 무시**: reducer와 컨트롤러 양쪽에서 가드. 졸음 경고(음성·경고음)는 시스템 주도라 주행 중에도 시작.
- **음성 수락 규칙**: 질문 직후 1회만 청취(상시 청취 없음). 경로를 덮어쓸 수 있는 상황에서는 다음절 명시 표현만 수락.
- **재경고 간격**: 같은 단계는 5분 뒤 반복, 더 높은 단계는 직전 발화 1분 뒤부터.

## 4. 주요 사용 시나리오

**사용자**: 장거리·야간 운전자, 영업·화물 운전자 (기획 원문의 타깃)

**이용 흐름 (에뮬레이터 시연 기준, 시연용 신호 주입 사용)**
1. 앱 실행 중 시연 신호(새벽 3시, 연속 주행 90분, 졸음 패턴 조향·속도)를 넣으면 약 20초 안에 위험지수가 58(주의)로 오르고 1단계 안내가 나옵니다(독립 검증 관찰).
2. 1단계에서 퀴즈를 시작했다가 응답이 없으면 2단계로 올라가 공조가 조절됩니다(풍량 3->7, 온도 22->20 관찰).
3. 3단계에서 공공데이터 스냅샷의 가까운 휴게소·졸음쉼터(예: 기흥(부산) 하행)를 제안하고 "응"(주입)으로 수락하면 내비에 경로 요청이 전달되고 내비 앱이 경로를 표시했습니다.
4. 정차 15분이면 누적 주행이 초기화됩니다(실제 15분 정차로 초기화 확인. 휴식 기록 생성은 시연 완료 처리로만 확인).

## 5. 개발 계획

**개발 환경**: Pleos Connect 에뮬레이터(AAOS 기반), Kotlin, Jetpack Compose, 최소 SDK 28 / target 35. 앱 ID `com.hmgcarapp.wakemate`.

**Pleos SDK 사용**

| SDK | 사용처 |
|---|---|
| Vehicle | 차속(CarPropertyManager 폴링), 기어, 조향각, 공조 조회·제어 |
| FusedLocation | 가까운 쉼터 계산(메모리에서만 사용, 저장·로그 없음) |
| NaviHelper | 경유지 추가(addWaypoint), 경로 요청(requestRoute) |
| TextToSpeech / SpeechToText | 안내, 응답 1회 청취(수동 request 방식) |

Pleos 디자인시스템 컴포넌트와 테마 토큰을 사용합니다.

**구조**: 위험지수는 순수 함수(`RiskEngine`)로 분리해 단위 테스트, 단계 전이는 순수 reducer(`WakeFlow`)와 실행기(`WakeRunner`), 연결·복구는 `ManagedConnection` 계열, 주행 시간·내기순환 시계는 별도 클래스.

**기획과 다르게 구현한 이유 (세 가지로 구분)**
- **SDK·플랫폼 한계**: 가속페달·차로 내 흔들림 신호 없음, 시동 신호 없음(`IgnitionState` 열거형만 있고 조회 API 없음), 운전자 ID 신호 없음, 내비 POI 검색 결과를 받는 API 없음(검색 화면 호출만 가능).
- **안전·개인정보 판단**: 개인 보정은 경계를 올리는 방향만, 음성은 질문 직후 1회만 청취(상시 청취 없음), 위치는 저장·로그 없음, 졸음 감지 정확도와 예방 효과는 주장하지 않음.
- **시간·범위상 미구현**: 시동 신호와 연동한 시작(시동 신호가 SDK 에 없어 불가. 대신 설정 '백그라운드 감시'를 켜면 화면 밖 감시·부팅 시 시작을 지원하며 에뮬레이터에서만 확인, 실차 미확인), 도로 방향 기반 쉼터 선택(후방 시설 제외 전방 필터는 구현), DMS 연동.
- **신호 조건·검증 불가로 미구현(시간·범위 사유 아님)**: 조향 엔트로피. 현재 조향 지표는 정지 후 급보정 횟수 규칙이며 학술적 조향 엔트로피가 아니다. SDK 조향각을 500ms 주기(2Hz)로 표집하고 실제 갱신 주기·정밀도는 실차에서 확인하지 못했으며, 에뮬레이터 조향은 계단 입력이고 졸음 레이블·실주행 데이터가 없다. 향후 실차 로그로 오프라인 비교 후 기존 규칙과 정보가 겹치지 않을 때만 보조 항으로 검토.

**기획 대비 달라진 점**

| 원문 기획 | 구현 결과 |
|---|---|
| 가속 페달 입력 감소, 차로 내 흔들림 지표 | SDK에 가속페달·차로 이탈 신호가 없어 **제외**. 조향 보정 패턴·속도 변동성(추세 제거)·내기순환 지속으로 대체 |
| 시동과 함께 백그라운드 동작 | 시동 신호는 SDK 에 없고(`IgnitionState` 열거형만 있고 조회 API 가 없음), 대신 설정 '백그라운드 감시'(기본 꺼짐, 동의 후·알림 필수·끄기 제공)를 켜면 비위치 포그라운드 서비스가 화면 밖에서 감시하고 재부팅 후 시작한다(에뮬레이터 확인, 실차 미확인). **설정이 꺼져 있으면 앱 실행 중에만 감시** |
| 운전자 식별/개인별 임계값 | 운전자 ID 신호가 없어 기기 단위 보정. "졸리지 않아요" 상향만 |
| 60 초과 1단계, 80 초과 쉼터 제안 | 구현은 40(주의)/60(경고)/80(위험) 3단계 경계 |
| 2단계 찬바람 | 외기 순환 + 풍량 증가 + 설정 온도 -2℃로 해석. 에어컨/전원은 켜지 않음(공조 전원이 꺼져 있으면 풍량 쓰기가 error code 2로 거부되고 그 사실을 알림) |
| 5km 앞 졸음쉼터 검색 | NaviHelper 에 POI 검색 결과를 받는 API 가 없어(검색 화면 호출만 가능) **번들 공공데이터 스냅샷(졸음쉼터 253 + 휴게소 215) + 직선거리**(도로 거리 미반영, 실시간 아님; 주행 중 유효한 진행 방향이면 후방 시설 제외). 갱신은 변환기 재실행, 공공누리 유형은 미확인 |
| 쉼터 휴식 후 재출발 시 초기화, "다음 휴식 1시간 30분 뒤" | **정차 15분 도달 시점에 초기화·기록**. 문구는 '연속 2시간 기준 남은 시간' |
| 응답 속도를 졸음 판단 보조 지표로 | 응답 시간은 단계 상승 판단에만 쓰고 지수에는 합산하지 않음. 시간은 질문 종료~인식 결과 도착의 근사 |
| 공개 연구의 조향 엔트로피 참고 | 구현하지 않음. 사유는 신호 조건·검증 불가(시간·범위 아님): 조향 지표는 정지 후 급보정 횟수 규칙이며 학술적 조향 엔트로피가 아니고, SDK 조향각을 500ms 주기로 표집하며 실제 갱신 주기·정밀도는 실차에서 확인하지 못함. 가중치의 연구 근거를 주장하지 않음 |
| DMS 카메라 연동 | 미구현(발전 방향) |

## 6. 기대효과 및 발전 가능성

- **사용자 가치**: 운전자가 스스로 알아차리기 전에 추정 지표로 휴식을 권하는 보조 수단을 목표로 합니다. **졸음운전·사고 예방 효과는 측정한 바 없으며 이 문서는 효과를 주장하지 않습니다.**
- **타깃 고객**: 장거리·야간 운전자, 영업·화물 운전자 (기획 원문).
- **예상 지표 [기획 가정]**: Pleos Connect 적용 10만 대 x 설치율 20% 가정 시 MAU 약 1.5만 명, 30일 리텐션 50% 목표. 근거 자료가 없는 가정이며 구현·측정 결과가 아닙니다.
- **향후 계획 (구현·검증하지 않음)**: 실주행 데이터 기반 가중치·임계 보정, 도로 거리·도로 방향 기반 쉼터 선택과 운영 정보 연동, DMS 등 직접 지표 결합(데이터가 공개될 때).

### 품질 체계 (구현 결과)
- 단위 테스트(clean 빌드): wake-mate 183건, core 82건(고유), 실패 0.
- 코드리뷰를 여러 차례 반복해 반영했습니다(내용은 `docs/apps/wake-mate/review-log.md`).
- 독립 런타임 검증(에뮬레이터, 코드 수정 없음): 11개 시나리오 PASS 10 / UNCERTAIN 1(세로 화면), FAIL 0. 낮음~중간 결함 D-1~D-7 기록. 상세는 [evidence/verification.md](evidence/verification.md).
- 2026-11-11 후속 검증(쉼터 실데이터·외기 제안, 에뮬레이터)과 수정분 재검증: 후속 8개 항목 중 PASS 7(일부 관찰·제한 기록 포함) / UNCERTAIN 1(recirc 쓰기 불가 차량, 재현 수단 없음), 재검증 W1~W4 PASS, FATAL 0건. 쉼터 실데이터 표시·직선거리 일치, 3단계 안내 음성(TTS 호출 로그)·외기 제안 수락/거절 분기, 퀴즈 정답·오답 경로는 에뮬레이터에서 확인했습니다(근거: [../verification.md](../verification.md) 맨 아래 두 절, 증거 40~55·70~75).
- 개인정보 고지(저장 항목, 위치 미저장, 기록 삭제 기능)를 명시.

### 알려진 한계 (정직한 고지)
- **환경상 미검증**: 세로(Portrait) 실화면, **실제 경고음 청취와 TTS 음성 청취**(에뮬레이터에서 소리 확인 불가, 로그·상태로만 확인), **실제 STT 인식**(음성 수락은 시연 주입으로만), **"괜찮아" 보정 경로의 실제 STT 입력**(퀴즈 정답 판정은 2026-11-11 후속 검증에서 에뮬레이터로 확인, 증거 54), 충분한 주행 후 실제 정차 15분의 휴식 기록 생성, 실차·실주행.
- **효과 미검증**: 위험지수는 추정이며 가중치·임계는 초기값. 졸음 감지 정확도, 오경보율, 예방 효과를 측정하지 않았습니다.
- **쉼터 데이터는 공공데이터 스냅샷(실시간 아님)** 이며 직선거리 기준입니다. 도로 거리·현재 운영 여부는 반영하지 않으며, 진행 방향은 주행 중(10km/h 이상) 유효한 값(0 초과 360 이하)일 때 후방 시설을 제외하는 데만 씁니다. 번들 데이터로 미리 계산한 기대 목록과 시연 주입 화면이 일치함을 확인했고(방위 정확히 0.0·정차·5km/h·방향 없음은 필터 없음), 실제 위치 수신 경로의 방위는 실차에서 확인하지 못했습니다. 실데이터 기준 쉼터 탭·3단계 안내는 2026-11-11 후속 검증에서 에뮬레이터로 확인했고(증거 41~44, 71~75), 아래 기존 증거 화면 중 가상 샘플 시절 캡처는 실데이터 기준으로 다시 찍지 않았습니다.
- 백그라운드 감시를 켜지 않았다면 앱이 꺼진 동안 감시하지 않습니다. 켠 경우 화면 밖에서도 감시하며 에뮬레이터에서 음성 안내(TTS)가 나오는 것을 확인했습니다. STT 는 녹음 시작까지만 확인했고 인식 결과, 부팅 직후 자동 시작된 서비스의 마이크 사용, 실차 동작은 확인하지 못했습니다. 경고음·공조 조절은 음성과 별개로 실행됩니다.
- 내비 경로는 에뮬레이터에서 실제로 표시되었으나 앱이 내비의 완료 이벤트를 받지 못하는 경우가 있었습니다. 이후 문구는 "내비에서 안내 시작을 확인하지 못했어요. 내비 화면에서 경로를 확인해 주세요."로 바꿔 단정하지 않게 했습니다(소스 확인). 이벤트를 못 받는 원인 자체는 고치지 않았고 수정 후 재검증도 하지 않았습니다(D-6).
- 주행 중 공조 쓰기: Vehicle SDK 에 `ERROR_DRIVING_RESTRICTED`(코드 50001)가 있어 이 코드를 "주행 중에는 차량 정책상 앱이 공조를 바꿀 수 없어요. 창문을 열어 환기해 주세요"로 안내하도록 처리했습니다(단위 테스트만 확인). 2026-11-11 후속 검증에서 에뮬레이터는 기어 D·60km/h 에서도 `ERROR_DRIVING_RESTRICTED` 없이 공조 쓰기를 허용해(외기 전환, 풍량 3->7, 온도 22->20; 증거 52·53) 거부 안내 문구는 화면으로 재현하지 못했습니다. 실차의 주행 중 정책 결과와 외기 순환 쓰기 불가 차량의 동작은 확인하지 못했습니다.
- 주행 전환 시 플랫폼 '주행 중에는 사용할 수 없습니다' 화면이 앱을 가린 사례 1회(재현 3회 실패, 원인 미확정, D-3). 2026-11-11 후속 검증의 D 60km/h 에서는 관찰되지 않았습니다.
- 같은 좌표를 다시 주입하면 위치가 갱신되지 않는 시연 UX 문제(D-2), 공조 전원 상태 반영이 10~15초 지연될 수 있음(D-4), 삭제 팝업 문구가 저장 항목 전체를 나열하지 않음(D-5).
- 신호 일시 부재 시 조향·속도 항목은 0점('수집 중' 표시)이 되어 지수가 낮게 나올 수 있음.
- 저장 데이터(설정, 보정값, 휴식 기록, 누적 주행 시간)는 기기 내 평문 저장(암호화 미적용). 앱 자체는 외부 전송을 하지 않으며 병합 매니페스트의 INTERNET 권한은 Pleos SDK 유래일 수 있음.
- 권한 대화상자는 주행 중 플랫폼이 차단하므로 설치 직후 정차 상태에서 허용해야 함.
